# AMO PyQt FMS

관제 운영자가 차량, 호출·배차, 운영 이벤트를 확인하는 데스크톱 앱입니다.
한국어·영어·중국어 간체와 라이트·다크 테마를 제공합니다. 첫 로그인 안내는 설정에서 끄거나 다시 볼 수 있습니다.

## 개발 환경에서 실행

Python 3.12와 `uv`가 필요합니다. Spring Boot 백엔드와 Vue 관리자 Web을 먼저 실행하세요.

```sh
cd GUI/MainControllerPC/AMOAdmin
uv sync --locked
AMO_FMS_API=http://127.0.0.1:18085 uv run --locked amo-fms
```

- `AMO_FMS_API` 기본값은 `http://127.0.0.1:18085`이고, `AMO_ADMIN_WEB_URL` 기본값은 `http://127.0.0.1:5175`입니다. 두 앱이 같은 백엔드에 연결되게 설정하세요. 다른 호스트의 주소에는 HTTPS를 사용하세요.
- 개발용 예시 데이터가 활성화된 백엔드에는 `operator@amo.test` / `AmoDemo!2026`으로 로그인할 수 있습니다.
- 지도와 로고는 저장소의 `maps/`를 읽습니다. 별도 경로가 필요하면 `AMO_MAP_DIR`을 지정하세요.
- **로그인** Web 게이트웨이에 접속합니다. 로그인 뒤 받은 접속 증표(JWT)는 앱이 실행되는 동안 메모리에만 보관합니다.
- **차량 상태 새로고침** Main Control에 개발용 IF-03 연결(TCP)로 접속합니다. 기본 포트는 18087입니다. 필요하면 AMO_FMS_TCP_PORT로 바꿉니다.

## 관리자 PyQt를 별도 실행

개발용 서버 두 개와 브라우저 로그인용 관리자 Web을 먼저 실행합니다.
같은 폴더에서 아래 명령을 각각 별도 터미널로 실행하면 관제와 관리자가
서로 다른 프로세스에서 열립니다.

```sh
uv run --locked amo-fms
uv run --locked amo-admin
```

`amo-admin`은 관제 상태를 주기적으로 조회하지 않습니다. 운영 현황·운영 로그를
열거나 새로고침하면 Web 게이트웨이의 운영 조회 API를 사용합니다. 회원·권한,
운행 이력, 시험 결과 등은 관리자 Web 및 통합 PyQt와 같은 서버 권한과 API를
사용합니다. 기본 메뉴는 운영자 6개, 관리자 8개이며 서버의 메뉴 노출 설정이
반영됩니다. 별도 관리자 앱에서 로그아웃하거나 창을 닫아도 관제 앱은 자신의
세션으로 계속 동작합니다. 한 프로세스에서 양쪽을 비교할 때는
`uv run --locked amo-fms-comparison`을 사용합니다.

편도 데모의 선결제·차액 결제, 경로 개정 단계, 최종 요금·영수증 및 복귀·충전 상태는 **운행 이력**에서 확인합니다. 운영 로그는 모의 IF-04·05·10 사건을 각각 표시합니다.

## 단계별 시나리오 검수

격리 PostgreSQL에서 Main Control을 `demo` 프로필로 실행하고 Web 게이트웨이를 연결합니다. 루프백 주소를 사용하는 별도 AMO Admin을 아래처럼 실행한 뒤 가상 관리자 계정으로 로그인합니다.

```sh
AMO_SCENARIO_REVIEW=1 uv run --locked amo-admin
```

1. **시나리오 검수** 탭에서 **Taxi · 경로 적용 성공과 복귀** 또는 **Taxi · 차액 결제 후 경로 적용 실패**를 고릅니다.
2. **새 검수 시작**을 누르고 목록의 ▶ 단계부터 클릭합니다. 원하는 중간 단계나 완료 단계를 바로 클릭하면 새 실행에서 선행 상태를 준비한 뒤 그 단계까지 자동 실행합니다. 단계 앞의 ✓는 관측 결과가 저장됐다는 뜻입니다. 이미 끝난 동작의 기록만 볼 때는 **단계를 클릭해 기록만 보기**를 켭니다.
3. 중간부터 볼 때는 원하는 단계를 선택하고 **이 단계 직전부터 새로 시작**을 누릅니다. 별도 가상 차량·충전칸으로 선행 단계가 재생되고 선택한 단계 앞에서 멈춥니다. 같은 단계 클릭은 기존 관측 결과를 사용합니다.
4. 화면 상단의 **호출 ID**를 기준으로 Android의 이용 내역과 FMS 호출 목록에서 같은 건을 확인합니다. FMS는 IF-03이 갱신된 뒤 적용 목적지를 표시합니다. Admin의 **이 호출의 운행 이력**은 같은 호출로 조회합니다.
5. 승객 입력을 직접 확인할 때는 **승객 단계는 Android에서 입력하고 결과만 확인**을 켭니다. Android에서 가상 승객으로 같은 호출의 견적·선결제나 S4 변경 요청·수락을 완료한 뒤 해당 단계를 다시 누릅니다. 중간부터 새로 시작할 때는 선행 단계가 자동 실행됩니다.

통합 PyQt에서는 `AMO_SCENARIO_REVIEW=1 uv run --locked amo-fms-comparison`으로 실행합니다. 오른쪽 시나리오 단계에서 재생을 요청하면 왼쪽이 운행 지도로 전환됩니다.

지도 시연을 보려면 FMS도 `AMO_SCENARIO_REVIEW=1 uv run --locked amo-fms`로 실행하고 **운행** 화면을 엽니다. 지도 상단에서 현재 단계와 시연 차량을 확인합니다. 픽업·출발·재출발·도착·복귀 단계에서 시연 차량 표식이 저장된 모의 위치 사이를 이동합니다. 변경 명령 접수와 경로 적용 단계에서는 위치를 유지하고, 재출발 이후에 다시 이동합니다.

단계 상세에는 기대 결과, 확인 화면, 서버 관측 시각과 적용 목적지·결제·영수증 등 해당 단계의 값을 표시합니다. 경로 접수 단계와 적용 실패 흐름에서는 S2를 유지합니다. 성공 흐름에서는 적용 보고 뒤 S4로 바뀌며 정차 후 재출발 보고는 별도 단계입니다. 지도 위치는 시연용 합성 표본입니다. 실제 차량 위치·주행 경로와 실물 신호는 별도 검증 대상입니다. ## 브라우저 로그인

1. FMS에서 **브라우저로 로그인**을 누릅니다.
2. 기본 브라우저에 열린 관리자 Web에서 AMO 계정으로 로그인합니다. 기존 브라우저 세션이 있으면 그 계정으로 연결을 확인합니다. 관리자 Web에 Google 로그인이 설정돼 있으면 해당 방식으로도 로그인할 수 있습니다.
3. 관리자 Web에서 **PyQt FMS에 연결**을 누른 뒤 FMS로 돌아옵니다. 승인된 `OPERATOR` 또는 `ADMIN` 계정으로 연결할 수 있습니다.

기존 로그인을 이어서 사용하려면 관리자 Web에 로그인한 것과 같은 브라우저 프로필에서 같은 주소를 사용하세요. FMS에서 브라우저 연결 대기를 취소하면 다시 시작할 수 있습니다.

## 개발 미리보기

- **운행 화면**은 Main Control이 IF-03으로 보낸 차량과 운영 기록을 보여 줍니다. 호출 목록의 원래 목적지와 일치하는 적용 보고를 받은 경로 개정을 따로 표시합니다. PostgreSQL은 Main Control이 읽습니다.
- **확정 도로 배치**를 기본으로 표시합니다. 저장 경로와 시나리오 재생은 기록의 좌표 기준인 v0.2 지도에서 확인합니다. 차량 위치를 확정 지도에 표시하려면 좌표 보정이 필요합니다.
- 최신 조회에 실패하면 이전 조회 결과와 갱신 실패를 함께 표시합니다.
- 호출 접수와 차량에서 관측한 운행 상태를 구분합니다. 조작 미리보기는 네트워크로 전송되지 않습니다.
- 개발 IF-03은 읽기 전용입니다. 실제 관제 명령과 이벤트 전달 계약은 팀 회의에서 정합니다.
