# AMO FMS comparison on Mac Studio

Measured on 2026-11-23 in a local macOS desktop session. Main Control and the
Web gateway used JDK 21. The database was PostgreSQL 17.11 and both clients used
the same database with 1,000,000 synthetic passengers, 100,000 synthetic ride
requests, 300,000 linked events, and 10,000 test history rows. The existing
operations response still returned three test summaries. No vehicle commands
were sent.

## Three repetitions per condition

Every run lasted 45 seconds and received four samples per second, one per
vehicle. The two workload modes each submitted six explicit searches, two per
screen, with 50 rows per page and at most one explicit search in flight. Web
navigation added its normal background requests. The order rotated on each
repetition. These measurements precede the addition of the on-demand route
detail dialog, which was separately verified with recorded and empty routes.

| Condition | Runs | Receipt → paint p95 (ms) | Poll RTT p95 (ms) | Qt receive → paint p95 (ms) | Longest fresh paint gap (ms) | Poll skipped / unfired / failed | Unpainted snapshot rows | Input rows not selected | Search failures |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| baseline | 3 | 450.8–924.3 | 35.0–36.9 | 8.6–8.7 | 7880.0 | 0/0/0 | 0 | 468 | 0 |

| Search endpoint | Web p95 range (ms) | Integrated PyQt p95 range (ms) |
| --- | ---: | ---: |
| `/api/admin/members/page` | 28.0–32.3 | 52.4–53.7 |
| `/api/operations/trip-history` | 21.3–23.2 | 45.9–48.4 |
| `/api/operations/test-history` | 14.9–16.4 | 33.3–35.4 |

Each range is the minimum and maximum of the three run-level p95 values.
Each search endpoint had two requests per run, so its run p95 is the larger
observation. Poll spacing and the phase of the 1 Hz input determine much of
receipt-to-paint time. The independently timed IF-03 and Qt segments show
the repeatable difference more clearly.

- The longest interval between fresh paints was about 7.88 seconds in all
  configurations. The integrated client added roughly 18–25 ms to the
  IF-03 p95 range compared with the Web condition and roughly 10–14 ms to
  the Qt receive-to-paint range. No poll skips, failed polls, or unpainted
  fetched samples were observed in the formal runs.
- Across each condition, 468 of 540 accepted input rows were never selected
  by a snapshot. The 7.5-second latest-state polling contract superseded
  those rows before a poll could present them.
- PostgreSQL buffer hits per run were 36,478–36,869 baseline,
  46,029–48,712 with Web, and 43,749–44,313 combined. Disk block reads ranged
  from 0 to 67 across all runs. Temporary bytes were zero.
- Process tree sample peaks for the Main JVM were 28.8%, 19.1%, and 10.1% CPU
  for baseline, Web, and combined respectively. Peaks for the Qt process tree
  were 4.3%, 2.8%, and 19.3%. Qt RSS peaks were 242,288, 238,480, and
  304,880 KiB respectively. These three-second samples do not establish
  sustained CPU load. Process tree RSS can double count shared pages.
- Standalone EXPLAIN showed an ordered account primary-key scan for the
  member query, the received-time index for the trip page, and sequential
  scans for the filtered trip and test counts. Plans and timings are
  specific to this fixture and cache state.

## Behavior checks and scope

The browser-to-Qt sign-in completed through the real Vue consent screen,
loopback callback and token exchange. The native comparison window showed
eight admin tabs and four IF-03 vehicle rows. The PyQt menu edit and original
label restoration were read back through the gateway. Synthetic pending staff
approval was read back as active. An operator attempting the member endpoint
was denied with HTTP 403. A delayed, failed IF-03 fixture distinguished an
in-flight skipped poll from a failed response.

The test measures a Qt paint completion rather than physical screen scanout,
and uses database reception time because no real vehicle ingress is active.
It covers one request-concurrency level and short local runs. It cannot
establish production latency limits, hardware control behavior, the maximum
sustainable query rate, or behavior on a different host.

See [reproduction instructions](README.md). Per-run traces, PostgreSQL plans,
and validation evidence are stored outside the repository.
